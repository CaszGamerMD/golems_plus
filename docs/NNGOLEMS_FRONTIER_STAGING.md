# Farm Demo frontier-staging pilot
An opt-in `GOLEMS_NN_FRONTIER_STAGING=true` works ONLY on NNGolems. A Builder with no claim and no executable direct frontier can walk through 6–12-block physically supported staging waypoints toward an unfinished, distant task. The planner never considers the intermediate waypoint a completed work target: it neither claims nor places any schematic block during the approach. After arrival it retries the normal support-, route- and exit-checked work planner. All legs are verified through WorkerNavigation.routeToExact; failed paths are rejected; 2 concurrent stagers and 780 ticks per worker/layer cap the work. No flight, rope or scaffold motion is interrupted; no return/recovery worker can stage. Recovery recognizes genuine physical movement toward an approved waypoint, only for its bounded duration. This tests whether far-away work stances were being rejected because A* could not establish a long direct route from OnSite. It does not bypass support or make scaffolding float.

Physical Farm Demo A/B holds teammate handoff OFF and partial project yield OFF, varying only GOLEMS_NN_FRONTIER_STAGING. Prior same-commit A/B showed partial return reached project 5 but only 185 correct, versus 422 with partial return off; therefore partial return stays off. This staging test separately measures exact correct blocks, ordinary placement, projects, retreats, successful waypoint arrivals and aborts. A GitHub workflow success indicates a completed assessment, not a finished farm or a validated 99% goal.
