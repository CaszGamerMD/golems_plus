### Current blockers (first complete-file import)

Original importer + block resolver: 107 unsupported palette variants.
After resolving inventory-backed block entities, redstone dust, and correctly
counted bed heads, 17 variants (759 cells) remained. Flowing water 1–6 is
now recognized as **17 non-item natural propagation positions**: the Builder
only completes them after the actual fluid state appears, never by writing
a synthetic water-level block. As of the latest full-file import, **11
unsupported generated-state variants affect 742 schematic cells**:

| Category | Cells | Requirement |
| --- | ---: | --- |
| Extended piston / sticky piston | 370 | Place retracted body, then power through real vanilla redstone |
| Piston heads | 370 | Generated by piston extension, NEVER an inventory item |
| Soul fire | 2 | Real ignition on soul sand with safe player/tool interaction |
| Flowing water levels 1–6 | 17 | Now modeled as source-dependent no-item state verification |

**Important: 131 of 370 extended pistons have their same-facing piston
heads ONE CELL BEHIND the base instead of in front.** The other 239 are
forward-aligned. `BuilderPistonAssemblyAudit.inspect` checks each pair's
local XYZ, direction, head type, and the would-be forward cell. These 131
pairs cannot be created through normal piston extension as encoded; they
might reflect a transient redstone snapshot. The user source is preserved
unchanged, never silently "fixed" by flipping a piston or head.

**Do not remove these cells or fake them with direct world-state writes.**
Full-build acceptance stays blocked until the actual saved geometry and
remaining redstone / ignition mechanics can be reproduced.

A **107/107** lower-layer result NEVER satisfies, replaces, or bypasses
the required **15,376/15,376** full-build acceptance.

On the first true bottom-up physical Matrix run, the crew reached **52/107**
cells with four living Builders, then stalled at source-local
`(15,1,24)`: `powered_rail[shape=ascending_west,waterlogged=true]`.
The requested raised-west connection is `(14,2,24)`, but the exact
user schematic reserves that upper cell for an `iron_trapdoor`, not a
rail. The paid temporary rail connector could make a slope momentarily,
but removing it caused the real rail shape to collapse. The Builder now
**defers further reshaping without consuming additional items** until
a permanent raised connection exists. This does not invent an upper
rail or silently change the user's blueprint. This is currently a
separate cross-layer / physical-rail-geometry blocker.

### Block-entity caveat

The original file includes 40 block-entity NBT records (e.g. container
inventories). The current production `LitematicFileReader` intentionally
does not restore block-entity NBT. The physical GameTest covers **block-state
geometry**; a separate block-entity content-restore feature/test is needed
before anyone claims a fully functional redstone machine clone.
